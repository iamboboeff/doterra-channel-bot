# doTERRA канал-бот

**Один** Telegram-бот, который держит в закрытых чатах только тех, у кого по doTERRA
набрано нужное число баллов (PV ≥ порога чата). Один и тот же бот обслуживает и
участников, и администратора — кто перед ботом, он определяет по личности
отправителя (`ADMIN_IDS` / `ADMIN_USERNAMES`).

Данные о баллах снимаются расширением/закладкой **doterra-export** (режим «👥 Команда»):
файл `ID · Имя · PV`.

## Как устроено

- **Участник** жмёт `Start`, присылает свой doTERRA ID. Хватает баллов — бот сразу
  даёт одноразовую ссылку в чат; не хватает — пишет, сколько ещё нужно.
- **Админ** пишет тому же боту `/start` (или `/admin`) и видит панель: «Обновить
  подписчиков» → присылает 1–2 CSV (два кабинета) → бот показывает список «на
  вылет» → подтверждает → удаляет. Кто тем временем добрал баллы — бот сам
  приглашает обратно.
- **Чаты-тиры** — закрытые чаты, у каждого свой порог баллов. Бот должен быть в них
  **администратором** с правами «Пригласительные ссылки» и «Блокировка пользователей».

## Настройка (один раз)

1. **Создай одного бота** у [@BotFather](https://t.me/BotFather) → `/newbot`. Получишь токен.
2. Впиши токен в `.env` как `BOT_TOKEN` (см. `.env.example`).
3. **Узнай свой user_id**: напиши боту `/whoami` и впиши число в `ADMIN_IDS`
   (можно вместо/вместе с этим указать `@username` в `ADMIN_USERNAMES`).
4. **Создай закрытые чаты-тиры**, добавь бота **администратором** в каждый
   (права: приглашать по ссылке + банить/удалять). ID чата и порог впиши в
   `TIERn_ID` / `TIERn_THRESHOLD` / `TIERn_NAME`.
5. Установи и запусти:
   ```bash
   npm install
   npm start
   ```

## Ежемесячно

1. В doTERRA сними команду закладкой «👥 Команда → CSV» (по разу на каждый кабинет).
2. Боту: `/admin` → «📥 Обновить файлом (CSV)» → выбери чат → пришли файл(ы) →
   «✅ Посчитать на вылет».
3. Проверь список (имя · ID · баллы) → «🗑 Удалить».

## Авто-приём из расширения (пуш) — без пересылки файла

Если включить, расширение **само отправляет баллы боту** при экспорте: файл
качать и пересылать не нужно. Удаление по-прежнему только по кнопке админа —
меняется только доставка данных.

Как это выглядит:

1. В расширении doTERRA один раз открой «⚙ Отправка боту», впиши **URL бота**
   (адрес приёма `…/ingest`) и **тот же секрет**, что `INGEST_SECRET` у бота.
2. Дальше как обычно жмёшь «Экспорт» → расширение снимает команду, скачивает CSV
   **и сразу шлёт боту**.
3. Боту прилетает: «📲 Пришли данные из расширения: N человек» + кнопки
   «Проверить: <чат>». Жмёшь чат → сразу список «на вылет» → «🗑 Удалить».

Два кабинета — просто экспортируй оба (за один месяц объединятся по максимуму
PV). Пропустил уведомление — открой `/admin` → «📲 Данные из расширения».

Включается двумя переменными у бота (см. `.env.example`):

- `INGEST_SECRET` — общий секрет (длинная случайная строка). Такой же — в расширении.
- `INGEST_PORT` — порт HTTP-приёма. На хостинге часто задаётся сам через `PORT`.

Если хоть одна пуста — приём выключен, всё работает по-старому (CSV файлом).
⚠️ Для пуша боту нужен **публичный адрес** — см. «Хостинг» ниже.

## Команды

- `/start` — участнику регистрация, админу — панель.
- `/admin` — явный вход в панель (для админа). Пока `ADMIN_IDS`/`ADMIN_USERNAMES`
  пусты, первые `MAX_AUTO_ADMINS` написавших `/admin` становятся админами (первичная
  настройка); после того как админы заданы — команда только для них.
- `/check` — участник проверяет свой доступ.
- `/whoami` — показать свой user_id.
- `/addadmin <ID | @username | +телефон>` — добавить администратора (только
  для действующих админов). Для телефона используй `phone +...`: человек затем
  пишет `/admin` и подтверждает свой номер кнопкой Telegram.
- `/admins` — показать администраторов и номера, ожидающие подтверждения.
- `/rebind <ID> <user_id>` — перепривязать doTERRA ID на другой аккаунт (админ).
- `/unbind <ID>` — снять привязку ID и выгнать из чатов (админ).

## Хостинг

Long-polling + файл `store.json` — работает локально, на VPS и на хостингах вида
bothost.ru. Теперь это **один процесс = один токен**: заводишь одну запись бота,
запуск `node bot.js` (`npm start`), переменные окружения — из `.env`/панели хостинга.

### Публичный адрес для пуша из расширения

Приём данных из расширения (`POST /ingest`) требует, чтобы у бота был **публичный
HTTPS-адрес/порт** — сам long-polling для этого не нужен, приём слушает отдельно.

- Если тариф даёт боту домен/порт (обычно тот же, что для вебхука) — задай
  `INGEST_SECRET`, при необходимости `INGEST_PORT` (многие хостинги подставляют
  `PORT` сами), и в расширении укажи адрес `https://<домен-бота>/ingest`.
- Проверить, что приём поднялся: открой в браузере `https://<домен-бота>/health`
  — должно ответить `ok`.
- Если публичного адреса на тарифе нет — пуш работать не сможет; остаётся обычный
  путь «прислать CSV файлом» (он никуда не делся). Тогда либо возьми тариф/VPS с
  портом, либо оставь ручную пересылку файла.

### Резервный бот (холодный резерв)

Второй бот держим как запасной. Код тот же — меняется только токен, и запущен
**всегда только один** бот за раз.

- На bothost заведи **вторую запись** из этого же репозитория. В ней `BOT_TOKEN` =
  токен второго бота, `STORE_DIR` — **та же** папка, что у основного (общий
  `store.json`). Держи запись **выключенной**.
- Упал основной — останови его запись и запусти запасную. Пороги, чаты и данные
  общие, ничего перенастраивать не надо.
- Второго бота тоже добавь **админом** в чаты-тиры (права: ссылки + бан).
- ⚠️ Одновременно должен работать только **один** бот. Два сразу — уведомления и
  ссылки разъедутся: Telegram привязывает переписку к конкретному @username.
- После переключения на запасного участники, чтобы снова получать от него
  сообщения, должны нажать Start у нового бота. Кик и выдача ссылок работают сразу.

### `STORE_DIR`

Путь, где лежит `store.json` (все регистрации и баллы). Если платформа стирает
файлы контейнера при перезапуске — укажи путь на постоянный диск (на bothost —
вид `/app/shared` после включения постоянного/общего хранилища), иначе после
рестарта регистрации потеряются.

## Безопасность

`.env` содержит токен бота — не публикуй его. В репозитории есть только
`.env.example`. Если токен где-то засветился — сразу перевыпусти его в @BotFather
(`/revoke` или /token заново), бот и его @username при этом сохранятся.

## Файлы

- `bot.js` — весь бот (участники + админка).
- `csv.js` — парсер CSV + авто-определение колонок ID/PV.
- `logic.js` — отбор «кого удалять» (порог, объединение кабинетов, защита «нет данных»).
- `store.js` — хранилище (файловое, `store.json`), в т.ч. «входящие» из расширения.
- `ingest.js` — HTTP-приём `POST /ingest` для авто-пуша из расширения.
