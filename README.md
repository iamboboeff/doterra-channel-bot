# doTERRA канал-бот

Связка из двух Telegram-ботов, которая держит в закрытом канале только тех, у кого
по doTERRA набрано нужное число баллов (PV ≥ порога, по умолчанию 50).

Данные о баллах снимаются расширением/закладкой **doterra-export** (режим «👥 Команда»):
файл `ID · Имя · PV`.

## Как устроено

- **Бот участников** — публичный. Человек жмёт `Start`, присылает свой doTERRA ID.
  Если баллов хватает — бот сразу даёт ссылку в канал; если нет — пишет, сколько не хватает.
- **Админ-бот** — только для тебя. Раз в месяц: меню → «Обновить подписчиков» →
  присылаешь 1–2 CSV (два кабинета) → бот показывает список «на вылет» → подтверждаешь → удаляет.
  Кто тем временем добрал баллы — бот сам приглашает обратно.
- **Канал** — пустой закрытый, оба бота в нём админы (право приглашать и банить).

## Настройка (один раз)

1. **Создай двух ботов** у [@BotFather](https://t.me/BotFather) → `/newbot` дважды.
   Получишь два токена.
2. **Создай закрытый канал**, добавь обоих ботов **администраторами**
   (права: приглашать по ссылке + банить/удалять).
3. **Узнай ID канала**: напиши админ-боту `/chanhelp` и следуй подсказке.
4. **Узнай свой user_id**: напиши админ-боту `/whoami`.
5. Скопируй `.env.example` → `.env` и впиши токены, `CHANNEL_ID`, `ADMIN_IDS`.
6. Установи и запусти:
   ```bash
   npm install
   npm start
   ```

## Ежемесячно

1. В doTERRA сними команду закладкой «👥 Команда → CSV» (по разу на каждый кабинет).
2. В админ-боте: «📥 Обновить подписчиков» → пришли файл(ы) → «✅ Посчитать на вылет».
3. Проверь список (имя · ID · баллы) → «🗑 Удалить».

## Хостинг

Long-polling + файл `store.json` — работает локально, на VPS, и на хостингах вида
bothost.ru, где **1 запись = 1 Telegram-токен**.

### Деплой одним процессом (VPS и т.п.)

Один запуск `node bot.js` держит оба бота. `ROLE` не задаём (по умолчанию `both`).
Нужны оба токена и постоянное место для `store.json` (см. `STORE_DIR` ниже).

### Деплой как ДВЕ отдельные записи (bothost.ru)

Заводишь на хостинге **две** записи бота, обе — из этого же репозитория/кода,
различаются только переменными окружения:

| | Запись «участники» | Запись «админ» |
|---|---|---|
| `ROLE` | `member` | `admin` |
| `MEMBER_BOT_TOKEN` | нужен | нужен *(чтобы слать участникам ссылки/уведомления)* |
| `ADMIN_BOT_TOKEN` | не нужен | нужен |
| `CHANNEL_ID`, `CHAT_ID`, `ADMIN_IDS`, `THRESHOLD` | одинаково в обеих | одинаково в обеих |
| `STORE_DIR` | **одна и та же** папка в обеих | **одна и та же** папка в обеих |

Важно: `STORE_DIR` должен указывать на **общее** постоянное хранилище (Volume /
Общее хранилище платформы) — обе записи читают/пишут один и тот же `store.json`,
иначе регистрации, известные боту участников, не увидит админ-бот (и наоборот).
На bothost это путь вида `/app/shared` после включения «Общего хранилища».

### `STORE_DIR`

Путь, где лежит `store.json` (все регистрации и баллы). Если платформа стирает
файлы контейнера при перезапуске — обязательно укажи путь на постоянный диск,
иначе после каждого рестарта все регистрации потеряются.

## Файлы

- `bot.js` — оба бота.
- `csv.js` — парсер CSV + авто-определение колонок ID/PV.
- `logic.js` — отбор «кого удалять» (порог, объединение кабинетов, защита «нет данных»).
- `store.js` — хранилище (пока файловое).
