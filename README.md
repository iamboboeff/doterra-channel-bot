# doTERRA канал-бот

**Один** Telegram-бот, который держит в закрытых чатах только тех, кто выполнил
условия доступа. Для команды «Анджелика» достаточно нужного числа баллов doTERRA,
для команды «Гость» дополнительно нужна подтверждённая ежемесячная оплата. Один и тот же бот обслуживает и
участников, и администратора — кто перед ботом, он определяет по личности
отправителя (`ADMIN_IDS` / `ADMIN_USERNAMES`).

Данные о баллах снимаются расширением/закладкой **doterra-export** (режим «👥 Команда»):
файл `ID · Имя · PV · Команда · Кабинет`.

## Как устроено

- **Участник** жмёт `Start`, присылает свой doTERRA ID. Команда определяется по
  выгрузке расширения. Анджелике при достаточных баллах бот сразу даёт ссылку;
  Гостю показывает оплату, передаёт заявку администратору и открывает доступ после
  подтверждения.
- **Админ** пишет тому же боту `/start` (или `/admin`) и видит панель. Красная
  выгрузка текущего месяца может только обновить баллы и пригласить. Зелёная
  выгрузка закрытого месяца предлагает отдельно удалить, пригласить или сделать
  оба действия. Удаление всегда требует подтверждения.
- **Чаты-тиры** — закрытые чаты, у каждого свой порог баллов. Бот должен быть в них
  **администратором** с правами «Пригласительные ссылки» и «Блокировка пользователей».

## Настройка (один раз)

1. **Создай одного бота** у [@BotFather](https://t.me/BotFather) → `/newbot`. Получишь токен.
2. Впиши токен в `.env` как `BOT_TOKEN` (см. `.env.example`).
3. **Узнай свой user_id**: напиши боту `/whoami` и впиши число в `ADMIN_IDS`
   (можно вместо/вместе с этим указать `@username` в `ADMIN_USERNAMES`).
4. **Создай закрытые чаты-тиры**, добавь бота **администратором** в каждый
   (права: приглашать по ссылке + банить/удалять). ID чата и порог впиши в
   `TIERn_ID` / `TIERn_THRESHOLD` / `TIERn_NAME`.
5. Установи и запусти:
   ```bash
   npm install
   npm start
   ```

## Команды и правила доступа

- `Анджелика`: PV должен быть не ниже порога выбранного чата.
- `Гость`: тот же порог PV плюс подтверждённая оплата за текущий месяц.
- Если один doTERRA ID оказался в выгрузках обеих команд, приоритет всегда у
  команды «Анджелика».
- Существующие записи без метки команды считаются командой «Анджелика».

В расширении у каждого аккаунта отдельно выбирается команда и задаётся уникальная
метка кабинета. Команда отвечает за правило доступа, метка — за замену повторной
выгрузки именно этого кабинета. Обе метки пишутся в CSV, имя Telegram-файла и его
подпись, поэтому команда не потеряется при ручной пересылке.

## Ежемесячная оплата гостей

По умолчанию сумма — `2 000 ₽`, льготный срок — два дня по московскому времени.
Сумма, реквизиты и срок меняются в `/admin` → «Оплата гостей». Новые значения
применяются к новым платёжным периодам; уже подтверждённая сумма сохраняется в
истории без изменений.

1. Гость с достаточными PV получает реквизиты и кнопку «Я оплатил(а)».
2. Заявка приходит в личный чат с ботом всем администраторам, чей Telegram ID
   известен боту. Первый администратор подтверждает или отклоняет её кнопкой.
3. После подтверждения бот выдаёт ссылку. Отдельная группа для оплат не нужна.
4. В начале нового месяца бот напоминает об оплате уже состоящим в чатах Гостям.
   После льготного срока неоплатившие автоматически удаляются. Позднее
   подтверждение снова открывает доступ при достаточных PV.

## Обновление баллов

1. В середине месяца нажми в расширении красный текущий месяц. Бот обновит только
   присланных людей, сохранит данные остальных и предложит только приглашение.
2. После закрытия месяца нажми зелёный месяц по каждому кабинету. Когда все файлы
   загружены, выбери чат и проверь списки ниже порога, отсутствующих в полных
   выгрузках и новых приглашённых.
3. Выбери нужное действие: «Только удалить», «Только пригласить» или «Удалить и
   пригласить».

Бот хранит максимум пять исходных выгрузок. `/admin` → «Обновить список
участников» → «Управлять выгрузками» позволяет удалить ошибочный файл или
переключить его между красным и зелёным режимом. Новая шестая выгрузка удаляет
самую старую. Если у файла указана метка кабинета, повторная выгрузка того же
кабинета за тот же месяц заменяет предыдущую.

## Регистрация существующих участников

`/admin` → «Кто не зарегистрирован» → «Начать сбор» публикует в выбранном чате
кнопку регистрации. Срока и автоматического удаления нет: когда администратор сам
решит, он снова открывает этот раздел, проверяет список и вручную подтверждает
удаление известных незарегистрированных. Telegram не отдаёт боту полный список
участников, поэтому отдельно показывается примерное число молчунов — их нужно
проверить вручную.

## Одноразовая очистка старого чата

Для первичной очистки чата, где сотни старых участников ещё не писали боту,
есть отдельный скрипт. Он не входит в обычную работу бота и не запускается по
расписанию.

1. Создай игнорируемый Git файл `cleanup.env` и добавь туда `TELEGRAM_API_ID` и
   `TELEGRAM_API_HASH`, полученные на [my.telegram.org](https://my.telegram.org) → `API development tools`.
2. Убедись, что бот — админ чата с правом банить участников.
3. Запусти только просмот:

   ```bash
   npm run cleanup:preview
   ```

   Отсканируй `cleanup-plans/telegram-login-qr.png` через Telegram на телефоне → «Настройки» →
   «Устройства» → «Подключить устройство». Личный аккаунт нужен только для чтения полного списка
   приватной группы. Его сессия не сохраняется и завершается сразу после операции.

   После входа preview сохранит в `cleanup-plans/` резервные JSON/CSV, покажет число удаляемых и точную
   фразу подтверждения. Владелец, админы и боты всегда исключаются. Дополнительных
   людей можно защитить через `PURGE_KEEP_USER_IDS`.
4. Отзови в Telegram все старые пригласительные ссылки. Только после этого скопируй команду,
   которую выдал просмотр. Без `--execute`, `--links-revoked` и точной фразы удаление не начнётся.

Скрипт удаляет людей из чата, но сразу снимает бан: позже они смогут вернуться по новой
личной ссылке от бота. Прогресс и ошибки пишутся в отдельный `result.json`.

## Авто-приём из расширения

Расширение скачивает CSV и одновременно отправляет его в приватный канал
«doTERRA импорт». Основной бот забирает документ из канала и добавляет его в
управляемые выгрузки. Можно также отправить этот же CSV основному боту вручную.

Как это выглядит:

1. Красная кнопка текущего месяца создаёт файл `doterra-current-…csv` — такой
   файл никогда не открывает удаление.
2. Зелёная кнопка закрытого месяца создаёт `doterra-closed-…csv` — после проверки
   доступны удаление и приглашение.
3. В настройках расширения обязательно выбери команду `Анджелика` или `Гость`.
   Метка кабинета нужна, чтобы повторная выгрузка заменяла именно этот кабинет.

Несколько кабинетов одного режима и месяца объединяются по ID; для повторяющегося
ID используется максимальный PV. Пропустил уведомление — открой `/admin` →
«Обновить список участников».

HTTP `/ingest` оставлен как дополнительный вариант для хостинга. Он включается
двумя переменными у бота (см. `.env.example`):

- `INGEST_SECRET` — общий секрет для совместимого HTTP-клиента.
- `INGEST_PORT` — порт HTTP-приёма. На хостинге часто задаётся сам через `PORT`.

Если хоть одна пуста — приём выключен, всё работает по-старому (CSV файлом).
⚠️ Для пуша боту нужен **публичный адрес** — см. «Хостинг» ниже.

## Команды

- `/start` — участнику регистрация, админу — панель.
- `/admin` — явный вход в панель (для админа). Пока `ADMIN_IDS`/`ADMIN_USERNAMES`
  пусты, первые `MAX_AUTO_ADMINS` написавших `/admin` становятся админами (первичная
  настройка); после того как админы заданы — команда только для них.
- `/check` — участник проверяет свой доступ.
- `/whoami` — показать свой user_id.
- `/addadmin <ID | @username | +телефон>` — добавить администратора (только
  для действующих админов). Для телефона используй `phone +...`: человек затем
  пишет `/admin` и подтверждает свой номер кнопкой Telegram.
- `/admins` — показать администраторов и номера, ожидающие подтверждения.
- `/backup` — скачать JSON-копию базы в личном чате с ботом (только админ).
- `/rebind <ID> <user_id>` — перепривязать doTERRA ID на другой аккаунт (админ).
- `/unbind <ID>` — снять привязку ID и выгнать из чатов (админ).

## Хостинг

Long-polling + PostgreSQL (с локальным `store.json` как страховкой) работает
локально, на VPS и на хостингах вида bothost.ru. Это **один процесс = один токен**: заводишь одну запись бота,
запуск `node bot.js` (`npm start`), переменные окружения — из `.env`/панели хостинга.

### Публичный адрес для HTTP-пуша

Дополнительный приём данных (`POST /ingest`) требует, чтобы у бота был **публичный
HTTPS-адрес/порт** — сам long-polling для этого не нужен, приём слушает отдельно.

- Если тариф даёт боту домен/порт (обычно тот же, что для вебхука) — задай
  `INGEST_SECRET`, при необходимости `INGEST_PORT` (многие хостинги подставляют
  `PORT` сами), а совместимый клиент должен отправлять данные на
  `https://<домен-бота>/ingest`.
- Проверить, что приём поднялся: открой в браузере `https://<домен-бота>/health`
  — должно ответить `ok`.
- Текущему Chrome-расширению публичный адрес не требуется: оно использует
  приватный Telegram-канал. Без публичного адреса также остаётся ручная отправка
  CSV основному боту.

### Резервный бот (холодный резерв)

Второй бот держим как запасной. Код тот же — меняется только токен, и запущен
**всегда только один** бот за раз.

- На bothost заведи **вторую запись** из этого же репозитория. В ней `BOT_TOKEN` =
  токен второго бота, `STORE_DIR` — **та же** папка, что у основного (общий
  `store.json`). Держи запись **выключенной**.
- Упал основной — останови его запись и запусти запасную. Пороги, чаты и данные
  общие, ничего перенастраивать не надо.
- Второго бота тоже добавь **админом** в чаты-тиры (права: ссылки + бан).
- ⚠️ Одновременно должен работать только **один** бот. Два сразу — уведомления и
  ссылки разъедутся: Telegram привязывает переписку к конкретному @username.
- После переключения на запасного участники, чтобы снова получать от него
  сообщения, должны нажать Start у нового бота. Кик и выдача ссылок работают сразу.

### PostgreSQL, локальная база и резервные копии

В Bothost создай PostgreSQL-базу и добавь выданный connection string в переменную
бота `DATABASE_URL`. При первом запуске бот сам создаёт таблицу и переносит туда
текущий `store.json`. После каждого изменения в PostgreSQL уходит полный актуальный
снимок: регистрации, баллы, команды, оплаты, администраторы и настройки. При новом
деплое данные автоматически восстанавливаются из PostgreSQL.

`STORE_DIR=/app/data` остаётся локальной страховкой. В нём лежит `store.json` с тем
же состоянием. Если PostgreSQL временно недоступна, бот продолжает работать с
файлом и показывает проблему в разделе «Статус».

Дополнительно бот автоматически создаёт снимки в `/app/data/backups`: `latest.json`
обновляется после каждой записи, а исторические снимки создаются при запуске и
затем не чаще раза в 6 часов (максимум 30 файлов). Если основной JSON повредится,
бот попробует прочитать последний исправный снимок. Команда
`/backup` отправляет админу отдельную копию через Telegram — её можно сохранить
на компьютере или в закрытом облачном диске. Не публикуй этот файл: в нём есть
Telegram ID и doTERRA ID участников.

## Безопасность

`.env` содержит токен бота — не публикуй его. В репозитории есть только
`.env.example`. Если токен где-то засветился — сразу перевыпусти его в @BotFather
(`/revoke` или /token заново), бот и его @username при этом сохранятся.

## Файлы

- `bot.js` — весь бот (участники + админка).
- `csv.js` — парсер CSV + авто-определение колонок ID/PV.
- `logic.js` — отбор «кого удалять» (порог, объединение кабинетов, защита «нет данных»).
- `store.js` — двойное хранилище (`store.json` + PostgreSQL), в т.ч. «входящие» из расширения.
- `postgres-store.js` — таблица JSONB, версии записей и защита от устаревшего снимка.
- `ingest.js` — HTTP-приём `POST /ingest` для авто-пуша из расширения.
- `billing.js` — команды, месячные периоды, рубли и расчёт льготного срока.
- `upload-meta.js` — совместимый разбор команды и кабинета из CSV и подписи расширения.
- `scripts/purge-chat.js` — одноразовая первичная очистка старого Telegram-чата с preview и двойным подтверждением.
- `purge-policy.js` — защита владельца, админов, ботов и расчёт фразы подтверждения.
